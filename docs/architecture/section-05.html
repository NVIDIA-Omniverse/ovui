Section 5

Scene Tools

After the atomic widgets in Section 4, ovui adds a scene package for Python code that needs camera-aware drawing, transforms, gestures, and manipulators inside the same windows and widgets as regular controls.

Purpose

omni.ui.scene gives a Python tool a way to draw scene content inside an ovui window. It does not open USD files or decide what is selected. It supplies the drawn objects, camera values, and input gestures that app code can combine with normal ovui widgets.

  • SceneView is the visible scene area that can sit in a ui.Window, ui.ZStack, or viewport.
  • Scene is the container reached through scene_view.scene; Python adds transforms, shapes, gestures, and manipulators there.
  • CameraModel supplies view and projection matrices so 3D shapes line up with the current camera.
  • Gestures attach to shapes or to Screen and call Python when the user clicks, drags, hovers, or scrolls.
  • ovwidgets uses these pieces in the viewport for camera motion, picking, transform gizmos, and selection outlines over the rendered image.

The scene area is not a separate app. It is one part of a normal UI window, so toolbars, fields, status text, and scene drawing can live together.

This keeps scene tools practical: a focused viewport can sit next to a few controls, and Python decides which shapes and gestures are present as the app state changes.

Python classes

The Python names divide into a small set of jobs: a view that hosts drawing, models that carry camera or manipulator values, objects that draw, and gestures that turn input into callbacks.

  • SceneView hosts the scene area; its scene property is where content is built.
  • Scene, Transform, and Screen organize objects, place them, and capture input across the whole scene area when needed.
  • CameraModel and AbstractManipulatorModel carry view, projection, and manipulator values as float or int arrays.
  • Manipulator rebuilds drawn content when its state changes; GestureBindingManipulator adds reusable gesture binding setup.
  • ClickGesture, DoubleClickGesture, DragGesture, HoverGesture, ScrollGesture, GestureManager, and GestureBinding cover common input behavior.

The names stay close to the job they perform. A viewport tool usually reads as: create a SceneView, keep camera values current, draw shapes in transforms, and attach gestures where user input should run Python code.

Common scene objects

Most scene code builds with a short vocabulary. The example ovui/examples/scene_manipulator.py creates a window, places a SceneView between a header and status row, draws a grid and cube with lines, and attaches drag or hover gestures to axis handles.

  • Shapes and display items include Line, Arc, Curve, Points, Rectangle, PolygonMesh, TexturedMesh, Image, and Label.
  • Transform moves, scales, or turns child items, so a gizmo can follow a selected object while each axis handle remains its own shape.
  • Screen is useful for camera gestures because it can receive input anywhere in the scene area.
  • Widget can place normal ovui widgets as a scene item, while regular ui.HStack, ui.VStack, labels, fields, and menus can still sit around the SceneView.
  • ovwidgets adds higher-level viewport objects such as CameraManipulator, TransformManipulator, PickGesture, and PickRectGesture; selection outlines are driven through the renderer adapter instead of a local scene manipulator.

Those pieces let a tool show more than a flat rendered image. The same window can contain the rendered frame, a camera gesture area, renderer-owned selection outline and highlight state, transform handles, and ordinary UI controls that change what the scene code draws.

How scene data reaches views

Scene data reaches a view through Python code that already knows the app state. The scene package draws what it is told to draw; app code, widget code, or adapter-backed state decides which objects exist, where they are, and what should happen when the user acts.

  • The ovwidgets viewport receives frames from RendererAdapter, shows them with ImageWithProvider, and places a SceneView in the same ui.ZStack.
  • CameraController supplies view and projection matrices to both the renderer and SceneView, keeping gizmos and renderer-owned outlines aligned with the rendered frame.
  • TransformManipulator reads selection and transform state through PrimTransformModel, then draws translate, rotate, or scale handles.
  • The viewport sends selection changes to RendererAdapter.set_selection_highlight(); the ovrtx adapter updates native selection-outline group state for the paths that changed.
  • PickGesture and PickRectGesture turn pointer input into viewport pick requests, and the pick result is published back to shared selection state.

For a custom scene tool, keep source data in Python objects or adapters, choose the visible shapes from that data, and call invalidate() when a manipulator should rebuild. The application then gives those scene pieces shared selection, settings, undo, and widget coordination.
